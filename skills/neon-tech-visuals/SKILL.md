# Neon Tech Visuals

暗く艶のある面に、アーク・回路トレース・輪郭線・点の群れが光り、その光が周りの壁を照らして映り込む。カメラが動くと外周が流れ、レンズの端で色がずれる。映像はシェーダー、音は numpy の合成で、素材は使わない。

仕組みは3層に分かれている。

- **シーン**（`scripts/scenes/*.glsl`）：形とカメラ。題材ごとに1ファイル
- **テック面**（`scripts/lib/common.glsl`）：2次元座標から段差と発光模様を作る関数。どの形にも貼れる
- **描画と仕上げ**（`scripts/lib/main.glsl`、`post.glsl`）：レイマーチ、映り込み、霧、モーションブラー、ブルームなど。全シーン共通

題材を変える依頼はシーンを選ぶか書き足す。質感や模様はどのシーンでも同じ設定で動く。

## 手順

### 1. 題材と設定を決める

同梱シーン：

| scene | 内容 | 向いている用途 |
|---|---|---|
| `tunnel` | うねる円筒の内側を飛び抜ける | 疾走感、オープニング |
| `city` | 回路基板のような街並みの上を低く飛ぶ | 横長の背景、落ち着いたループ |
| `core` | 回路で覆われた球体と光の輪を周回する | タイトル背景、製品・データの象徴 |

これ以外の題材を頼まれたら、`references/scenes.md` を読んで新しいシーンファイルを作業フォルダに書く。40行ほどで書ける。ユーザーが題材を指定しなかったときは、参考動画があればそれに近いシーン、なければ用途から選ぶ。

作業フォルダに `config.json` を置く。書かなかった項目は `scripts/defaults.json` の値になる。

```json
{
  "name": "opening",
  "scene": "tunnel",
  "width": 1280, "height": 720, "duration": 8,
  "seed": 7, "bpm": 128,
  "quality": { "preset": "standard" },
  "look": { "palette": "circuit-green", "speed": 8, "warp": 1.0, "density": 1.0 },
  "audio": { "style": "drive" }
}
```

画面は横長1280×720が既定。縦長は、ユーザーが縦・リール・ショート・ストーリーズ向けと言ったときだけ 720×1280 にする。正方形は 1080×1080。魚眼は画面の対角を基準にしているので、向きを変えても画角の設定はそのまま使える。

ユーザーの言葉を設定に訳すときの目安：

| 言われたこと | 触る項目 |
|---|---|
| 色を変えたい | `look.palette`：`circuit-green` / `cyber-magenta` / `ice-blue` / `amber-heat` / `mono-white`。ブランド色は `{"colors":[[r,g,b]×5],"weights":[5個]}` を直接書く（0〜1のリニア値、先頭が主色） |
| 速く・ゆっくり | `look.speed`（tunnelで5がゆったり、12で疾走）。`bpm` も合わせる |
| うねり・蛇行 | `look.warp`（0で直進、1.6で強い） |
| 広角に・歪みを抑えて | `look.fov`（シーン既定への倍率。0.8で控えめ、1.2で強い魚眼） |
| 情報量 | `look.density`（0.6〜1.5。光る要素の割合が変わる） |
| 回転を止める | `look.roll`: 0 |
| 画質を上げたい・もっと滑らかに | `quality.preset`: `high` か `max`（解像度もfpsも上がる。下の「画質」を参照）。動きの滑らかさだけなら `fps`: 60 |
| 流れを強く・くっきり | `quality.shutter`（0でブラーなし、0.4が既定、0.8で強い） |
| 艶・映り込み | `look.reflect`（0〜2） |
| 眩しい・暗い・にじみ | `look.exposure`、`look.bloom` |
| 色ずれ・粒子 | `look.aberration`、`look.grain` |
| 拍で光らせたい・やめたい | `look.pulse`（0でなし、0.5が既定、1.5で派手） |
| 絵柄を変える | `seed` |
| 落ち着いた音・無音 | `audio.style`: `ambient`、`audio.enabled`: false |

### 画質

`quality.preset` で解像度の倍率、重ね描きの回数、ブラーの細かさ、圧縮率をまとめて切り替える。`width`/`height` は standard のときの大きさとして書き、preset が倍率を掛ける。

| preset | 出力（横長の場合） | fps | 重ね描き | 1枚の時間※ | 8秒の所要※ |
|---|---|---|---|---|---|
| `standard`（既定） | 1280×720 | 30 | 1回 | 6〜8秒 | 約30分 |
| `high` | 1920×1080 | 60 | 2回 | 約30秒 | 約4時間 |
| `max` | 2560×1440 | 60 | 3回 | 約80秒（推定） | 約10時間（推定） |

※GPUなしの1コア環境（SwiftShader）での目安。`render.js` は起動時に実機のGPUを探し、あればそれで描く（表示される `renderer:` で分かる）。GPUのあるマシンでは桁違いに速いので、high や max はそちらで回すのが現実的。

fpsは最上位の `fps` に書けば preset より優先される。動きの滑らかさだけ欲しいなら standard のまま `"fps": 60`（所要は倍）、解像度だけ欲しいなら high で `"fps": 30`（所要は半分）。モーションブラーは1コマの時間に対する割合（`quality.shutter`）で掛かるので、60fpsにすると1コマの流れは短く、動きは細かくなる。音と拍の同期はfpsに依らない。

個別に変えたいときは `quality` に直接書けば preset より優先される：`scale`（解像度の倍率）、`samples`（重ね描き。輪郭のギザギザが減る）、`blurTaps`（モーションブラーの粒の細かさ）。圧縮は最上位の `crf`（小さいほど高画質で大きい。16〜24）。4Kは `"width":1920,"height":1080,"quality":{"preset":"max"}`。

中間フレームは無劣化のPNGで持つ。1枚あたり 720pで約2MB、1080pで約4MBなので、長尺の前にディスクの空きを確かめる。

時間のかかる画質を頼まれたら、先に所要時間を伝えて、尺を短くするか standard で絵を固めてから上げるかを相談する。絵づくり（色・速さ・密度）は必ず standard か preview で済ませ、決まってから preset を上げる。同じ `seed` と設定なら、解像度を上げても同じ絵になる。

### 2. プレビューで詰める

```bash
python3 scripts/build.py preview config.json work
```

6コマを半解像度で描いて `work/preview.jpg` に並べる。必ず画像を見て、白飛び・暗すぎ・線の潰れ・色の偏り・カメラが壁に埋まっていないかを確認する。半解像度は線が太く明るく出るので、最終判断は等倍の1枚でする。

```bash
node scripts/render.js config.json --out work/full --frames 60
```

### 3. 本番を描く

```bash
python3 scripts/build.py render config.json work --budget 240
```

240秒で区切って終わり、描けた枚数を表示する。「全フレーム完了」と出るまで同じコマンドを繰り返す（描画済みのコマは飛ばす）。裏で走らせたプロセスはツール呼び出しの合間に止まる環境があるので、前面で区切って回す。

設定やシーンを変えたら `work/frames` を消してから描き直す。古いコマが混ざると途中で絵が変わる。`duration` を短くするだけなら消さなくてよい。

### 4. まとめて確認する

```bash
python3 scripts/build.py finish config.json work /mnt/user-data/outputs/<name>.mp4
```

音を合成し、H.264/AACのMP4にまとめ、10コマの一覧 `work/sheet.jpg` と平均輝度を出す。一覧を見て、輝度が目安（25〜90）に収まっているか、音のRMSが秒ごとに極端に上下していないかを確かめる。30MBを超えて渡せないときは、表示された crf に4を足した値を `config.json` に書いて finish だけやり直す。

### 5. 渡す

MP4を `present_files` で渡す。返答は短く、シーン・色・速さ・BPM・尺と、次に変えられる点を2〜3個添える。音は数値でしか確認していないので、聴いた感想をもらえれば直せると伝える。

## 設定で届かない変更

- 新しい題材、カメラワーク、形の変更 → `references/scenes.md`
- 模様の追加、質感、仕上げ、音のフレーズ、不具合の直し方 → `references/internals.md`

共通ライブラリを書き換えるときは `scripts/` ごと作業フォルダにコピーして、そちらを編集して使う。スキル本体は書き換えない。

## 守ること

- 参考動画を渡されても、その作品を複製しない。色・速さ・密度・レンズ感といった作風の要素を設定に訳し、模様は `seed` から新しく生成する。作者名やアカウント名を映像に入れない。
- 音は毎回 `seed` から作るオリジナルにする。参考動画で鳴っている曲のメロディやフレーズはなぞらない。既存曲を使いたいと言われたら、無音で書き出してユーザー側で権利のある音源を載せてもらう。
- 既存のキャラクターや他社のロゴを形として作らない。ロゴや文字を載せる依頼は、ユーザー自身のものだけ finish 後に ffmpeg の `drawtext` / `overlay` で重ねる。
